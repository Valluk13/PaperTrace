# Калибровка порога фильтра надёжности

Статус: таблицы ниже — **черновые цифры** (`--no-llm`, 0 токенов LLM). **Финальные цифры с
LLM-признаками: precision 0.893, recall 0.962, F1 0.926 при пороге 0.5; максимум F1 0.946 при
пороге 0.3** — см. `report.md`, «Дополнительные разрезы». Выбран порог 0.5 (проигрывает оптимуму
один FN) ради воспроизводимости системы между прогонами; авторитет по цифрам — `report.md`.

## 1. Зачем

`RELIABILITY_THRESHOLD = 0.5` (`reliability_rag.py:17`) и веса признаков подобраны вручную.
Чтобы на защите ответить на вопрос «почему 0.5?» данными, а не «нам так показалось», порог
прогнали по сетке 0.3–0.7 и сравнили вердикты фильтра с независимой ручной разметкой
двух человек.

## 2. Данные и метод

- `dump_papers.py` → `papers.json`: 29 уникальных статей по 4 темам (пайплайн с фильтром
  надёжности, без писателя и верификатора).
- Разметка: два **независимых** разметчика (`rater1`, `rater2`); каждый работал только с
  `reliability_rubric.md` и CSV с пустыми колонками меток, метки друг друга не видел.
  Согласованный вердикт — `final_label`, спорные случаи — с обоснованием в `comment`.
- Свип порога без сети и без LLM: `python threshold_sweep.py papers.json reliability_labels.csv --no-llm`.
  Признаки считаются один раз (`has_code_link`, `has_limitations` — regex по полному тексту
  `abstract + pages_text`; `venue` из OpenAlex), перебирается только порог.

## 3. Разметчики и согласие

|        | good | trash |
|--------|------|-------|
| rater1 | 27   | 2     |
| rater2 | 26   | 3     |

- Совпадение: **28/29 = 96.6 %**, Cohen's κ = **0.78** (высокое согласие).
- Итоговая разметка (`final_label`): **26 good / 3 trash**.
- Единственное расхождение — `2411.18583` («Automated Literature Review Using NLP Techniques
  and LLM-Based RAG», ICISET 2024): rater1 = good (критерий А формально выполнен: датасет
  SciTLDR, численное сравнение ROUGE), rater2 = trash. После обсуждения согласовали trash:
  небольшая прикладная статья, сравнение готовых систем без нового метода; пограничный случай
  решён консервативно. Примечательно, что фильтр на regex-признаках даёт этой статье 0.55
  (код + limitations + venue) — она же оказывается основным FP фильтра; программа здесь
  согласна с первоначальной оценкой rater1, а не с итоговой.

- Без LLM максимальный балл = 0.55 (0.30 код + 0.15 limitations + 0.10 venue; признаки
  `has_dataset`/`has_baseline_comparison` недоступны), поэтому пороги ≥ 0.55 отбрасывают всё.
- Precision почти не зависит от порога (~0.9); в черновом режиме узкое место — recall.
- FP при пороге 0.3: `2411.18583` (0.55) и `2308.02443` «AI Literature Review Suite»
  (ровно 0.30 — ссылка на код в тексте есть, но статья описывает инструмент без какой-либо
  оценки: ни данных, ни сравнений).

## 5. Выбранный порог

- На черновых данных максимум F1 — при пороге **0.3** (0.809 против 0.541 у текущего 0.5).
- Но черновой режим заведомо пессимистичен: `paper_type = unknown` (ветка «обзор/теория»
  с базой 0.6 не работает), `has_dataset` и `has_baseline_comparison` не считаются
  (до −0.45 балла у эмпирических статей). С LLM-признаками баллы надёжных статей вырастут
  сильнее, чем у мусора, и оптимум может сместиться вверх.
- Решение: `RELIABILITY_THRESHOLD` в коде **пока не меняем**. Финальный порог утверждаем по
  таблице с LLM-признаками (`python threshold_sweep.py papers.json reliability_labels.csv`,
  29 LLM-запросов) — это будет отдельный коммит.

## 6. Обзорные статьи: гипотеза «не могут быть отброшены»

- Код: у `survey`/`theoretical` база 0.6 + бонусы (venue 0.2, код 0.1, limitations 0.1) →
  минимум 0.6 > 0.5. При текущем пороге 0.5 обзорная статья не может быть отброшена
  в принципе (`reliability_rag.py:81–82`).
- Разметка: в выборке 2 обзора — `2504.20119` («Can LLMs Be Trusted for Evaluating RAG
  Systems?», IEEE SDS) и `2511.00776` (SLR по галлюцинациям в коде, 60 статей); оба
  получили good у **обоих** разметчиков. Случаев «обзор-мусор прошёл фильтр» в данных нет.
- Итог: гипотеза **подтверждается** (на уровне кода + без опровержений в разметке).
  Побочный эффект виден и в цифрах: без LLM-классификации обзоры получают низкие
  эмпирические баллы (`2511.00776` → 0.15) и попадают в FN — черновой recall занижен
  именно из-за этого.

## 7. Ограничения

1. n = 29 — метрики грубые (одна статья ≈ ±0.03–0.04 F1).
2. Черновой режим `--no-llm` пессимистичен (см. §5); финальные цифры будут выше.
3. `papers.json` закоммичен **с полным `pages_text`** (~2 МБ): regex-признаки считаются по
   `abstract + pages_text` (`reliability_rag.py: full_text`), и только так цифры таблицы
   воспроизводимы. Закоммиченный `dump_papers.py` сохраняет `papers.json` без текста
   страниц — при полной повторной выгрузке `has_code_link`/`has_limitations` будут
   определяться только по аннотации, и цифры будут ниже.

## 8. Состав

`dump_papers.py`, `papers.json` (29 статей с текстами страниц), `reliability_labels.csv`
(rater1, rater2, final_label, comment), `threshold_sweep.py`, `reliability_calibration.md`.
