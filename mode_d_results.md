# Режим D: внешний продукт с поиском против нашего режима C (Задача 2)

Вход: 5 ответов внешнего продукта (ZCode (GLM + веб-поиск), ответы получены 06.11.2026) на темы q01–q05
из eval_dataset_big.json; формулировка темы подаётся как есть. Ссылки извлечены
регуляркой arXiv-ID, каждая проверена скачиванием с arXiv (pages_of); то же
правило «существует = скачивается», что и в режимах A/B/C.

| Метрика | Наш режим C | Внешний продукт |
|---|---|---|
| Существование ссылок (ID скачивается с arXiv) | — (файл eval_results.json недоступен (FileNotFoundError(2, 'No such file or directory'))) | 100% (16/16 ссылок) |
| Поддержка текстом статьи (судья) | — | н/д* |
| Верная страница указана | — | 0%** |
| Ответы с хотя бы одной несуществующей ссылкой | н/д (в бенчмарке не считалось) | 0 из 5 (0%) |

\* Поддержка судьёй для внешних ответов не считается: без указания страницы сравнивать не на чем.
\** «Страница» у внешнего продукта = предложение явно называет страницу (стр. N / p. N / page N).
Внешние продукты не выдают наш формат [arXiv:ID, стр. N], поэтому строгий CITE_RE из common.py
сюда не применяется — это конструктивное различие форматов, а не метрика «указал страницу неправильно».
Ограничение регулярки: числа вида «2024.12345» (год.число) матчатся как потенциальный arXiv-ID;
каждая проверка записана в mode_d_details.json, сомнительные случаи проверяются вручную по нему.
Утверждений (предложений) во внешних ответах: 32, из них ссылаются на arXiv-ID: 16,
явно называют страницу: 0.

## Что важно при чтении

- Из 16 уникальных arXiv-ID во внешних ответах скачиваются 16, не существуют 0.
- Каждый ответ внешнего продукта с битой ссылкой — это потенциально сфабрикованная цитата в обзоре;
детали по каждой ссылке: mode_d_details.json.
- Наш режим C по конструкции цитирует только скачанные статьи (см. ограничения в README),
  поэтому сравнение существования ссылок — ключевое: оно отделяет «нашли и проверили» от «звучит правдоподобно».
